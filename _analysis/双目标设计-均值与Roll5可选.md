# 双目标设计：均值 / Roll5 用户可选

> 需求：**两种目标都保留，由用户选择走均值还是 Roll5。**
> 本设计基于你的真实阵容数据（`火沙耶主c`，CV 12.02%）实测验证。
> **本轮零新增战斗**（全部基于已复现的 100 场真实分布）。

---

## 0. 核心设计结论：一次搜索服务两种目标

**关键发现：不需要两套搜索。**

因为 `Roll5 ≈ 均值 + 1.162964 × 标准差`，两种目标只差**一个排序键**：

| 模式 | 排序键 |
| --- | --- |
| **均值** | `mean` |
| **Roll5** | `mean + 1.162964 × sd` |

**所以架构改动很小**：
1. 每个候选**额外记录标准差**（作者目前只记均值——这是最小、最关键的缺口）
2. 最终排序时按用户选择切换排序键
3. **阶段流水线、采样、缓存、并行全部不用改**

## 1. 两种目标的分歧有多大（实测）

在合理邻域内随机取配置对（均值 ±6%、标准差 0.5~2.5 倍）：

| | 比例 |

| **两目标选出不同赢家** | **36.7%** |

| A 均值 | A 标准差 | B 均值 | B 标准差 | 均值选 | Roll5 选 |
| ---: | ---: | ---: | ---: | :---: | :---: |
| 83,602,741 | 11,547,462 | 81,289,358 | **15,434,769** | A | **B** |

## 2. 排序键的精确形式（含小样本修正）

### 2.1 标准差的偏差问题（我实测发现并修正）

`statistics.stdev` 对**方差**无偏，但对**标准差**有偏（`E[s] = c4(n)·σ`，`c4(n) < 1`）：

| n | c4(n) | sd 低估 |
| ---: | ---: | ---: |
| 2 | 0.797885 | **20.21%** |
| 4 | 0.921318 | 7.87% |
| 8 | 0.965030 | 3.50% |
| 16 | 0.983484 | 1.65% |
| 32 | 0.991969 | 0.80% |

> ⚠️ **我在测试过程中一度得出"c4 修正让结果更差"的错误结论。** 原因是我当时拿**同一样本的经验 Roll5** 当参照——而那个参照本身在小样本下就是**偏低**的（n 个点的最大值低估真实最大值）。改用**总体真值**（40 万样本）后，结论反转。

### 2.2 三种估计量与总体真值的偏差（干净对照）

真值：`Roll5(population) = 94,275,827`

| n | 经验公式偏差 | 闭式偏差 | **闭式 + c4 偏差** |
| ---: | ---: | ---: | ---: |
| 2 | **−6.65%** | −2.48% | **−0.03%** |
| 4 | −3.45% | −0.98% | **−0.01%** |
| 8 | −1.77% | −0.45% | **−0.02%** |
| 16 | −0.88% | −0.20% | **+0.00%** |
| 64 | −0.23% | −0.06% | **−0.02%** |

**结论**：
- **经验公式在小样本下严重偏低**（n=2 时 −6.65%）——它无法看到自己要估计的上尾
- **闭式 + c4 修正几乎无偏**（各 n 都在 ±0.03% 内）

### 2.3 排序准确率（搜索真正需要的）

两候选：A = 你的分布；B = 均值 ×0.97、标准差 ×1.7。**真值选 B**。

| n | 均值键 | 经验 Roll5 | 闭式 | **闭式 + c4** |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 42% | 52% | 57% | **58%** |
| 4 | 39% | 57% | 61% | **62%** |
| 8 | 36% | 70% | 72% | **73%** |
| 16 | 30% | 78% | 81% | **81%** |
| 32 | **23%** | 86% | 88% | **88%** |
| 64 | **14%** | 94% | 96% | **96%** |

**注意"均值键"那一列：14%~42%，随种子增多而下降** —— 再次确认均值在 Roll5 目标下无效。

**闭式 + c4 在每一档都是最优或并列最优。**

## 3. 建议的实现

### 3.1 目标模式

```python
class Objective:
    MEAN = "mean"      # 稳定输出：日常刷取，追求可预期
    ROLL5 = "roll5"    # 当日最高：冲榜、活动排名
```

用户界面：一个单选/下拉，两个选项。**默认值建议 MEAN**（与现有行为一致，向后兼容），并把 ROLL5 标为"冲高"。

### 3.2 排序键（一行核心逻辑）

```python
C5 = 1.162964          # E[max of 5]，已在你阵容上验证

def rank_key(samples, objective):
    m = mean(samples)
    if objective == MEAN:
        return m
    sd = stdev(samples)               # n>=2
    return m + C5 * sd / c4(len(samples))     # c4 修正小样本偏差
```

`c4(n) = sqrt(2/(n-1)) * exp(lgamma(n/2) - lgamma((n-1)/2))`

### 3.3 每个候选要记录的数据

| 字段 | 现状 | 说明 |
| --- | --- | --- |
| `mean` | ✅ 已有 | |
| **`sd`** | ❌ **缺失** | **必须新增——这是最小且最关键的改动** |
| `n`（样本数） | ✅ 已有（种子数） | 用于 c4 |

**作者花 256 个种子精确估计均值，却没记标准差——只需再记一个数，Roll5 就直接算出来了。**

### 3.4 必须按模式区分的机制

| 机制 | 位置 | 均值模式 | **Roll5 模式** |
| --- | --- | --- | --- |
| `mean > max(gap×ref, 3×SE)` 波动惩罚 | `quick_review.py:38` | 安全 | **有害——系统性淘汰高方差=最优候选** |
| "波动/临界保护"保留 | `quick_review.retain` | 合理 | 保护了低方差平庸候选 |
| 排序键 | 全流程 | `mean` | `mean + C5×sd/c4` |

**建议**：把波动惩罚做成模式相关。或者在 Roll5 模式下**直接关闭它**（它也消耗种子，且其统计前提在 Roll5 下不成立）。

### 3.5 采样量（必须满足较严格的那个）

Roll5 是更难估计的统计量（极值、小样本偏低），**它决定下限**：

| 目标精度 | 需要种子数 |
| --- | ---: |
| Roll5 误差 < 2% | **8** |
| Roll5 误差 < 1% | **16** |
| Roll5 误差 < 0.5% | **32** |

**建议**：最低 8 个种子，决策阶段 16~32。**均值模式可以沿用较少种子**，但为了两种模式共用一次搜索，**采样量按 Roll5 的要求设定**。

### 3.6 结果的呈现

同一批样本可以**同时**给出两个排序：

| 展示 | 内容 |
| --- | --- |
| 主结果 | 按用户所选模式的冠军 |
| 副结果 | 另一模式下的冠军 + 两者的 Roll5/均值对比 |
| 明确标注 | "本结果按 **Roll5** 目标选出" |

**当两模式冠军不同时，应同时显示两者**——这对用户是有价值的信息（"稳定方案 vs 冲高方案"），而不是需要隐藏的分歧。
