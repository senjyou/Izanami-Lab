# 未精评的 159 个候选，会不会影响输出的最优阵容？

> 用户问题：使用**自动预估预算**，仍有 159 个未精评 —— 这些未精评的**是否影响最优阵容的输出**？

## 一、先确认账目：预算是被完整用掉的，没有浪费

复现用户那次的数字（预算 828、空间 210、Roll5、精评 8 种子）：

```
reserve            = max(8×2, 828//3) + 8 = 284
affordable battles = 828 - 284 = 544
coarse_cap         = 544 // 2 = 272   →  screened = min(272, 210) = 210
粗筛花费            = 210 × 2 = 420
精评预算            = (828-8) - 420 = 400  →  50 个候选
加 baseline        = 1
=> 精评 51 个   ← 与日志「精评 51」一致
=> 未精评 159   ← 与日志「其余 159」一致
=> 总花费 = 420 + 408 = 828   ← 恰好用满预算
```

**结论**：自动估算没有算错，也没有闲置预算 —— 828 场全部用于「粗筛全部 210 个 + 精评其中 51 个」。

## 二、直接回答：**不影响，已实测**

用与用户运行**同结构**的合成战场（210 候选、预算 828、CV 2.7–4.8%、前 10 名间距约 3%），
把「部分精评」与「**全部 210 个都精评**」（预算 60,000）对比：

| 指标 | 实测 |
| --- | --- |
| 两次运行**选出的冠军相同** | **16 / 16（100%）** |
| 中位落后于真最优 | **0.0000%** |
| 最差落后于真最优 | 0.1862% |
| 真最优**被粗筛丢掉**（从未精评） | **0 / 16** |
| 真最优已精评但排名被压低 | 2 / 16 |

**在真实的 CV 区间（2.7–4.8%）里，真最优 20/20 都进入了精评名额**（中位粗筛排名第 1，最差第 6）。

所以那 159 个未精评的候选**不包含比冠军更好的阵容** —— 它们不是"被跳过的机会"，而是**已经用便宜的方式证明过不如冠军**的候选。

## 三、真正的限制不是"未精评"，而是**样本数不够**

同一批候选，比较「8 种子的测量值」与「真实值」：

| 名次 | 测量值 | 真实值 | 误差 |
| ---: | ---: | ---: | ---: |
| #1 | 128,525,838 | 130,467,075 | −1.49% |
| #2 | 128,483,855 | 130,644,006 | −1.65% |
| #3 | 128,119,934 | 130,306,263 | −1.68% |

而**真实的 #1 与 #2 只差 0.135%**。

> 那个 −1.5% 不是估计器有偏（蒙特卡洛实测偏差 ≤0.03%），而是**固定的 8 个精评种子本身的均值不为零**
> （本次 −0.49 个标准差单位），使**所有候选**的绝对分数被同向平移。排序不受影响（共同随机数），
> 但报告的绝对分数会带上这个平移。

### **提高精评种子数确实能改善前几名的排序**（已实测）

构造一个真实 Roll5 只差 **0.049%** 的对子（A 均值高 0.135% 但波动低；B 均值低但波动高，
**B 才是真正更好的**），测「搜索能否挑对」：

| 精评种子数 | 挑对的比例 |
| ---: | ---: |
| 2 | 58.7% |
| **8（当前默认）** | **75.7%** |
| 16 | 83.9% |
| 32 | 92.2% |
| 64 | 97.5% |
| 128 | 99.8% |

**所以：想让"前几名谁更好"更可靠，就提高「精评种子数」。** 8 个种子对几乎并列的候选只有约 3/4 的把握。

> ⚠️ 我一开始推断"差距太小、加种子也没用"，**那是错的** —— 我当时的测试给两个候选喂了**完全相同的种子**，
> 共同随机数把噪声抵消了，于是永远 100% 正确，看不出任何差别。改成各自独立的抽样后才暴露真相：
> **加种子有效，而且效果很大。**

## 四、一个真实风险：粗筛在 2 种子下是**双峰**的

粗筛的排序键在 n=2 时化简为：

```
rank_key = mean + 1.0306 × |x₁ − x₂|
```

对**波动远高于全场**的候选，这意味着：

- 两次抽样**差异大** → 排序键很高 → 排到最前；
- 两次抽样**恰好接近** → 排序键塌回均值 → **排到最后**（实测最差第 210/210）。

也就是说它**几乎不会排在中间**，而是要么最前要么最后。

**实测影响**（把真最优设为一个「均值低 2.5%、CV 11.5%」的高波动候选，全场 CV 3%）：

| 粗筛种子数 | 粗筛覆盖 | 精评名额 | 真最优进入精评 | 从未被粗筛 |
| ---: | ---: | ---: | ---: | ---: |
| **2** | 210 | 50 | **16/20（80%）** | 0 |
| 4 | 136 | 34 | 13/20（65%） | 7 |
| 8 | 68 | 34 | 3/20（15%） | 17 |
| 16 | 34 | 34 | 1/20（5%） | 19 |

**注意这个反直觉的结果**：提高粗筛种子数**反而更差** —— 因为它成比例地消耗预算，
导致能粗筛的候选总数从 210 降到 34，真最优**根本没被筛到**。

**但在用户真实的 CV 区间（2.7–4.8%）内，这个风险很小**：波动差距不足以让排序键塌陷，
真最优 20/20 都进了精评。**风险只在「某张回忆卡让波动远高于其他组合」时才会显现**（例如极限堆暴击）。

## 五、想全覆盖要多少预算？

| 方案 | 战斗数 | 精评覆盖 |
| --- | ---: | ---: |
| 自动估算（当前） | 828 | 51 / 210（24%） |
| **全部精评** | **2,108** | **210 / 210（100%）** |

即 `210×2 粗筛 + 210×8 精评 + 8 baseline = 2,108`，是自动估算的 **2.5 倍**。

但由第三节可知：**这多花的 1,280 场并不能让前几名的排序变准**，只能把"错过真最优"的概率进一步压低
（而它本来就已是 0/16）。**对当前的 CV 区间，自动估算的 828 场是够的。**

## 六、结论与建议

| 问题 | 答案 |
| --- | --- |
| 159 个未精评会影响最优阵容吗？ | **不会。** 全部精评后冠军相同（16/16），真最优从未被粗筛丢掉（0/16）。 |
| 那它们是什么？ | 已用 2 种子证明过**明显不如冠军**的候选，不值得再花 8 倍成本。 |
| 那真正的风险是什么？ | ① **前几名真实差距太小**（实测 #1/#2 只差 0.135%），8 个种子只有约 **3/4** 的把握挑对；② 若某组合**波动远高于全场**，2 种子粗筛可能把它甩到最后。 |
| 怎么改善？ | 想让**前几名排序更可靠**：提高**精评种子数**（8 → 16/32/64，实测 8→32 把握从 76% 升到 92%）。想让**高波动组合不被甩掉**：手动把它的回忆卡设为**必选**，或把卡池缩到十几张。**不要**去加粗筛种子数 —— 那会减少能粗筛的候选总数，反而更差。 |

> **一句话**：未精评的不是风险，**精评种子数不够才是**。
> 要提升可信度，请加「精评种子数」，**不要**加「预算」，也**不要**加「粗筛种子数」。

## 七、过程中的自我纠错记录

| 我的错误 | 后果 | 修正 |
| --- | --- | --- |
| 测试里用 `memory_ids[0]` 取变动的回忆卡 | `derive()` 会**排序** `memory_ids`，实际读到的是最小的 id（永远是 2），等于所有候选都是同一个 | 把变动 id 放在五个常量**之下**，用 `min()` 取回 |
| 约束里没把 5 张常量卡标为**必选** | 空间变成 `C(210,6) = 1108 亿`，而不是 210，测的根本不是同一个问题 | 5 张标必选、210 张标候选 → `C(210,1) = 210` |
| 推断"差距太小，加种子也没用" | 结论**完全反了** | 原因是测试给两个候选喂了**相同种子**，共同随机数抵消噪声；改成独立抽样后测得加种子效果显著（8→32 从 76% 升到 92%） |
| 猜测 −1.5% 偏差来自"经验式估计偏低" | 探针显示 n=6000 只低 0.05%，**假设被自己的数据否证** | 查明真因是固定种子的均值非零（−0.49σ），造成全体同向平移 |
