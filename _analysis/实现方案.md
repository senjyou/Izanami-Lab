## 1. 算法设计

### 1.1 核心洞察：为什么可以大幅简化

补丁版的复杂度来自**多阶段共同种子筛选**（裸装 2→4→8 → 剪枝 → 联合覆盖 → 入围 → 快速复评 8~256 → 决赛 50+100）。实测证明这套框架：

| 实测结论 | 对设计的影响 |
| --- | --- |
| 真实差距中位数 **14.24%**，5/7 对 >10% | **粗筛极其有效**，不需要复杂淘汰 |
| 1 种子判定一致率 **90%**，2 种子 **95.9%** | 粗筛用 1~2 种子即可 |
| Roll5 需要 ~8 种子（1 种子低估 12%） | 精评用 8 种子 |
| 按均值排序在高方差下命中率降至 **14%** | 必须支持 Roll5 目标 |
| 站位影响 > 回忆 **3.7 倍** | 站位是主维度 |

**结论**：把"多阶段阈值筛除"换成 **"粗筛 + 定种子精评 + 按目标排序"**，用 1/10 的复杂度得到等价或更好的结果。

### 1.2 流水线（4 步）

```
[1] 枚举候选空间
      站位排列 × 回忆组合（受约束过滤）
      不跑战斗，纯计算

[2] 粗筛：每候选 1 个种子
      按预算上限截断（例如最多 N 个候选）
      目的：砍掉明显劣势尾部，不做精确排名

[3] 精评：对粗筛存活者评 8 个种子（Roll5 默认 / 均值 2 个）
      预算不足时按粗筛排名优先

[4] 排序输出
      均值模式：key = mean
      Roll5 模式：key = mean + 1.162964 × sd / c4(n)
      同时报告经验 Roll5（不假设分布）
```

**可选自适应**（推荐但非必需）：精评后若某候选实测 CV > 8%，追加到 16~32 种子。

### 1.3 目标函数（`objective.py`）

```python
import math, statistics

C5 = 1.162964          # E[max of 5]，数值积分 + 蒙特卡洛双重验证

def c4(n):
    """E[s]/sigma，修正 stdev 的小样本偏差（n=2 时低估 20.2%）"""
    if n < 2:
        return float("nan")
    return math.sqrt(2.0 / (n - 1)) * math.exp(
        math.lgamma(n / 2.0) - math.lgamma((n - 1) / 2.0))

def roll5_empirical(samples):
    """模拟器已有公式：E[max of 5]，不假设分布形状"""
    xs = sorted(samples); n = len(xs)
    return sum(x * ((i / n) ** 5 - ((i - 1) / n) ** 5) for i, x in enumerate(xs, 1))

def rank_key(samples, objective):
    """搜索期排序键：只需两个矩，小样本稳定"""
    m = statistics.mean(samples)
    if objective == "mean" or len(samples) < 2:
        return m
    sd = statistics.stdev(samples)
    return m + C5 * sd / c4(len(samples))

def summary(samples, objective):
    """返回展示用完整统计"""
    return dict(
        n=len(samples),
        mean=statistics.mean(samples),
        sd=statistics.stdev(samples) if len(samples) > 1 else 0.0,
        min=min(samples), max=max(samples),
        roll5=roll5_empirical(samples),
        rank=rank_key(samples, objective),
        sorted=sorted(samples))
```

**为什么排序用闭式、报告用经验式**：
- 闭式只需 2 个矩 → 小样本稳定，实测在全部 10 个预设上误差 ≤0.36%
- 经验式需要覆盖上尾 → 小样本偏低（1 种子低估 12%），但 n 大时无分布假设

### 1.4 候选枚举（`space.py`）

```python
def enumerate_candidates(tab_state, scope, constraints):
    """生成待评估候选。不跑战斗。"""
    positions = legal_positions(tab_state, constraints)   # 站位排列
    if scope.memories:
        memories = memory_combinations(constraints)       # C(池, 6-必选)
    else:
        memories = [current_memories]
    for pos in positions:
        for mem in memories:
            yield make_state(tab_state, pos, mem)
```

**模式差异**：

| 模式 | 站位空间 | 备注 |
| --- | --- | --- |
| 战术演习 | 5 人 × 6 槽 = **720** | 单队 |
| 对抗压制战 | 同上 720 | 单队 + 赛季/阶段 |
| 复合战术演习 | **3 队**，每队 6 槽 | 空间为 3 队联合；v1 建议只优化其中一队，其余固定 |

**v1 简化建议**：复合模式先只支持**单队优化**（其余两队固定），把 3 队联合留到 v2。

### 1.5 采样与预算

| 阶段 | 种子数 | 目的 |
| --- | ---: | --- |
| 粗筛 | **1** | 淘汰明显劣势 |
| 精评（Roll5） | **8**（默认，按你的决定） | 可信排序 |
| 精评（均值） | **2** | 向后兼容 |
| 自适应追加 | **16~32** | 当实测 CV > 8% |

**预算换算**（以战术演习 720 站位 + 1 组回忆为例）：

| 配置 | 战斗数 |
| --- | ---: |
| 粗筛 720 × 1 | 720 |
| 精评前 40 名 × 8 | 320 |
| 自适应 Top-8 × 16 | 128 |
| **合计** | **~1,168** |

对比补丁版同场景 `720×8 = 5,760` 场（裸装预选）——**约 1/5 的战斗量**。

### 1.6 评价器扩展（`engine.py`）

需支持三种控制器（都在官方代码里现成）：

```python
class Evaluator:
    def __init__(self, base_path, user_data_dir, mode):
        ...
    def evaluate(self, state, seed) -> float:
        random.seed(seed)                       # 官方引擎用全局 random
        bf, dl = self.battlefield(state)
        if self.mode == "tactical":
            c = TacticalExerciseController(bf, BattleConfig(max_turns=5, enable_rdps=False), dl)
            return float(c.execute_battle()["score"]["total_score"])
        if self.mode == "circle":
            c = CircleBattleController(bf, cfg, dl, season=..., stage=...)
            ...
        if self.mode == "composite":
            c = CompositeTacticController(bf, cfg, dl, teams=..., team_memories=..., boss_unit_id=...)
            ...
```

**注意**：`engine.py:107` 用 `random.seed(seed)` 操作**全局 RNG**（官方引擎如此），必须保存/恢复环境 RNG（现有实现已正确处理）。
