# 回应：Roll5 目标 + 兔沙耶高方差 —— 为什么这彻底改变了优化目标

> 你的三点信息：① 优化目标是 **Roll5（当日最高）**；② 兔沙耶（発情バニー）四拐一阵容上下限极大，因其技能是**暴击累进 buff**；③ 回合数越长差距越大。
> **第 ① 点是最关键的，它推翻了作者算法乃至我之前所有分析的前提。**
> 第 ② ③ 点我尝试复现但**没能做到**，我会如实说明为什么，以及为什么这不影响第 ① 点的结论。

## 0. 最重要结论：优化目标错了，整个算法的方向就错了

我用**零战斗**的模拟（用模拟器自己的 Roll5 公式）验证：

| 对比 | 结果 |
| --- | --- |
| 两个阵容：A 均值略高、方差低；B 均值略低、方差高 | |
| **按均值选 → 选 A；按 Roll5 选 → 选 B** | **30 组中有 14 组（47%）结论相反** |

**接近一半的情况下，"均值最优"和"Roll5 最优"是不同答案。**

### Roll5 奖励方差（这是关键）

同样均值、不同 CV 下，Roll5 相对均值的提升：

| CV | 均值 | Roll5 | **Roll5/均值** |
| ---: | ---: | ---: | ---: |
| 2% | 10,002,427 | 10,233,520 | 1.023 |
| 5% | 9,991,529 | 10,567,202 | 1.058 |
| 10% | 9,972,061 | 11,145,570 | **1.118** |
| 20% | 10,026,232 | 12,333,211 | **1.230** |
| 30% | 10,026,962 | 13,548,381 | **1.351** |
| 50% | 10,158,445 | 15,936,295 | **1.569** |

**在 CV=30% 时，单纯因为波动大，Roll5 就比均值高 35%。** 而兔沙耶的暴击累进机制正是制造高 CV 的引擎。

### 这对作者算法的三重否决

| 作者算法的做法 | 在 Roll5 目标下的后果 |
| --- | --- |
| 用**共同种子均值**排序 | **看不到** Roll5 优势——同均值高方差的阵容会被低估 |
| 整个预算用于**缩小均值的置信区间** | 花在了**错误的统计量**上。Roll5 由**上尾**决定，需要分布形状，不是更紧的均值 |
| 快速复评用 `mean > max(ratio×ref, 3×SE)` **惩罚波动** | **主动淘汰**高方差候选——正好淘汰掉 Roll5 最优的阵容 |

**第三条尤其严重**：作者的噪声保护机制（"波动/临界保护"）本意是保守，在 Roll5 目标下变成了**系统性地筛掉正确答案**。

## 2. 为什么这**不**削弱第 0 节的结论

第 0 节的结论是**结构性**的，不依赖具体方差大小：

> 如果优化目标是 `E[max of 5]`，而算法按**均值**排序并**惩罚波动**，那么当候选的方差不同时，两者会选出不同答案。

这个论证是纯数学的（我用模拟器自己的 Roll5 公式，零战斗验证）。**它成立与兔沙耶的实际 CV 是 3% 还是 30% 无关**——方差越大，分歧越严重；方差小，分歧也依然存在（我的表里 CV=3% vs 8% 就已经出现分歧）。

**所以：无论我的复现成功与否，"优化目标需要从均值改成 Roll5"这个结论都成立。**

## 3. 需要改的东西（按依赖顺序）

### 3.1 第一优先：把目标函数换成 Roll5

模拟器**已经有现成实现**（`tactical_exercise.py:1062`）：

```python
# Roll5 期望：每日5次演习取最高分
# E[max of 5] = Σ_i x_(i)·[(i/N)^5 − ((i−1)/N)^5]，x_(i) 为升序第i个分数
```

**但注意：这个公式需要 N 个样本的经验分布。** 样本少时（例如 2 个种子）`E[max of 5]` 无法可靠估计——**这直接回答了你的上一个质疑**：

> **在 Roll5 目标下，单种子/双种子不仅"不够精确"，而是数学上无法计算。** 我需要至少足够多的样本才能估计上尾。

**所以你要的答案在这里**：不是"单种子够不够"的问题，而是**目标函数决定了必须多采样**。

### 3.2 由此推出的采样需求

要估计 `E[max of 5]`，需要能刻画上尾的样本量。粗略地：
- 要估计 5 次抽样的最大值分布，至少需要几十个样本才有意义
- 具体需要多少，取决于分布的尾部厚度（兔沙耶那种厚尾需要更多）

**这与作者算法的取向完全相反**：作者用 2/4/8 个种子估计**均值**；Roll5 目标需要**几十个**样本来刻画**分布**。

### 3.3 这重新解释了作者算法的"冗余"

作者的多阶段共同种子阶梯（8/16/32/64/128/256）**本意是缩小均值误差**。在 Roll5 目标下：
- 这些种子**不该用于缩小均值**
- 而应该用于**刻画每个候选的分布上尾**
- 也就是说，**种子应该集中花在少数候选上，而非分散筛选**

## 4. 修正后的方向

| 项 | 原方案（我上一轮） | 修正后 |
| --- | --- | --- |
| 优化目标 | 平均分 | **Roll5 = E[max of 5]** |
| 判定统计量 | 均值 ± 2×SE | **分布上尾（分位数 / Roll5）** |
| 种子用途 | 缩小均值误差 | **刻画分布形状** |
| 单种子粗筛 | 可行（90% 一致率） | **仅可用于剔除明显劣势者，不可用于最终排序** |
| 高方差候选 | 应被"波动保护"保留 | **可能是最优解，应主动寻找** |
| 需要样本量 | 1–8 | **几十个**（估计上尾） |

## 5. 我的错误总结

1. **我前几轮一直在优化"如何更准确地估计均值"**，而没有先问"目标是不是均值"。**这是方向性错误**——你一句话就指出来了。
2. **我用合成阵容测试，缺少真实拐的配合**，导致复现失败。我应该在发现复现不了时**更早**告诉你"我需要真实阵容数据"，而不是继续加测试。
3. 我上一轮说"1 种子足够"时，隐含假设了目标是最小化均值误差。**在 Roll5 下这个结论不成立。**
