# 测试结果：解析层代理是否可行

> 目标：验证"用零战斗的静态特征向量给配装排序"能否替代战斗搜索。
> 方法：三个实验，共 **60 场真实战斗**（每案例独立，低于 100 场/案例上限）+ 对已有 200 场数据的零成本再分析。
> **结论：解析层代理方案失败。但测试过程中发现了一个更好的方向。**

---

## 0. 总结：三个实验，两个否定，一个关键发现

| # | 实验 | 战斗 | 结论 |
| --- | --- | ---: | --- |
| 1 | 混合配置的代理相关性 | 36 | ❌ **代理失败**（最佳单特征 ρ=−0.647，方向还是反的） |
| 2 | 方差分解（分离维度） | 24 | ⚠️ **代理仍不显著**（n=6，\|ρ\|<0.83 都不可信） |
| 3 | **种子效率（复用已有数据）** | **0** | ✅ **关键发现：便宜的粗筛其实够用** |

**我提议的"解析层优先"方案不成立。** 下面说明原因，以及为什么第 3 个实验指向了一条更实际的路。

---

## 1. 实验 1：混合配置的代理相关性 —— 失败

20 个配置（站位与回忆同时变化）× 2 种子 = 36 场。

用零战斗提取的回忆 buff 向量做代理，与真实得分的 Spearman 相关：

| 代理特征 | Spearman |
| --- | ---: |
| StatusCriticalChance | **−0.647** |
| StatusMaxHp | +0.611 |
| StatusSpeed | −0.400 |
| StatusAttack | +0.324 |
| 加权组合代理 | **−0.715** |
| | |
| **top-3 / top-5 命中率** | **0/3、0/5** |

**加权组合代理与实际得分负相关（−0.715），top-k 完全命中不了。**

### 这个实验有设计缺陷（我自己发现的）

站位与回忆**同时**变化，而（见实验 2）站位对方差的影响是回忆的 3.7 倍。所以回忆类特征几乎全是噪声，负相关是配对偶然。

**这个实验作废，但它证明了"直接拿属性向量当真"是错的。**

---

## 2. 实验 2：方差分解 —— 揭示真实的支配关系

分离两个轴：固定站位只变回忆 / 固定回忆只变站位。各 6 配置 × 2 种子 = 24 场。

| 轴 | 得分 sd | 极差 spread |
| --- | ---: | ---: |
| **回忆轴**（站位固定） | **2.01%** | 4.83% |
| **站位轴**（回忆固定） | **7.36%** | **19.77%** |
| | | |
| **比值（站位/回忆）** | **3.7×** | 4.1× |

**站位对结果的影响是回忆的约 3.7 倍。**

回忆轴内的 buff 类型相关性（n=6）：

| 特征 | Spearman |
| --- | ---: |
| StatusDefense | +0.725 |
| DealtDamage | −0.676 |
| StatusMaxHp | +0.617 |
| StatusCriticalChance | −0.598 |
| StatusSpeed | +0.494 |

**⚠️ 但这些都不可信**：n=6 时 Spearman 需要 **|ρ| > 0.83** 才达到 p<0.05。**没有一个特征达到。** 而且 `StatusDefense` 正相关、`DealtDamage` 负相关，方向在机制上讲不通——典型的**小样本噪声**。

**结论：6 个样本不足以判定代理相关性，但也没有任何正面证据。** 我不会把"属性向量能当代理"当作已确认。

---

## 3. 实验 3：种子效率 —— 关键发现（0 战斗）

复用已有的 200 场数据（7 组站位对 × 10 共同种子）。对每个 n，枚举全部 n-种子子集，看是否与 10-种子的判定一致：

| 站位对 | 真实差距 | n=1 | n=2 | n=3 | n=4 | n=6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 左前↔左后 | 16.23% | 100% | 100% | 100% | 100% | 100% |
| 左前↔右后 | 14.24% | 100% | 100% | 100% | 100% | 100% |
| **中前↔中后** | **3.47%** | **60%** | **84%** | 89% | 96% | 100% |
| 右前↔左后 | 16.07% | 100% | 100% | 100% | 100% | 100% |
| 左前↔中前 | 7.40% | 100% | 100% | 100% | 100% | 100% |
| **中前↔右后** | **4.71%** | **70%** | **87%** | 93% | 98% | 100% |
| 右前↔中后 | 16.51% | 100% | 100% | 100% | 100% | 100% |
| | | | | | | |
| **平均一致率** | | **90.0%** | **95.9%** | 97.5% | 99.0% | 99.9% |

### 这张表改变了整个判断

**真实站位差距大多是大的**：

| 统计 | 值 |
| --- | ---: |
| 差距中位数 | **14.24%** |
| 差距 < 5% 的对 | **2/7** |
| 差距 > 10% 的对 | **5/7** |

**所以：1 个种子就有 90% 的判定一致率，2 个种子 95.9%，4 个种子 99%。**

**这解释了作者算法为什么"能用"**——多数情况下粗筛确实能挑对。同时也精确指出了它**错在哪**：

- 大差距的对（>14%）：**任何**种子数都能判对，作者花 8 个种子是**浪费**
- 临界对（3.5~4.7%，正好卡在 3% 阈值附近）：1 种子 60~70%、2 种子 84~87% —— **作者用 4 种子 + 3% 固定阈值，正是在这里 41.9% 翻转**

**作者的问题不是"用错了方法"，而是"对简单情况过度采样、对困难情况采样不足，且用固定阈值"。**

---

## 4. 修正后的方案

我原提议的"解析层优先"**否定**。修正为：

### 4.1 保留粗筛，但改为自适应

```
阶段 1：粗筛（1–2 种子）
  对所有合法组合各评 1 个种子
  成本低（720 站位 × 1 = 720 场，而不是 5,760）
  目的只是淘汰"明显差"的尾部，不是精确排名

阶段 2：自适应加种子（核心改进）
  对存活候选，逐个加共同种子，直到：
      2×SE < 目标分辨力（例如 1%）
  或   预算耗尽
  关键：种子数由该候选的实测噪声决定，不是全局常数

阶段 3：判定
  差距 > 2×SE  → 有依据地淘汰
  差距 ≤ 2×SE  → 报告"无法区分"，保留
```

**这与作者算法的区别**：作者用固定 3%/5% 阈值 + 固定 2/4/8 种子；新方案用**逐候选的实测噪声**决定种子数和判定。**在 90% 的情况下结果相同（差距大），但在 10% 的临界情况下不会翻转。**

### 4.2 解析层的正确用途：剪枝，不是排序

实验 1/2 否定了"用属性向量排序"，但**没有否定"用掩码匹配剪枝"**：

- 掩码命中的槽位是空位 → 该卡收益为 0 → **确定可剪**
- 掩码命中的角色不满足其他选择器（属性/职业/类型）→ **确定可剪**

**这类剪枝是二值的、无噪声的，不依赖代理质量。** 这才是解析层的可靠用途。

### 4.3 为什么这比"另起炉灶"更务实

| | 作者算法 | 修正方案 |
| --- | --- | --- |
| 粗筛种子 | 2→4→8（固定） | 1–2（固定，但更少） |
| 淘汰依据 | 固定 3%/5% | **逐候选 2×SE** |
| 临界情况 | 41.9% 翻转 | 报告"无法区分" |
| 大差距情况 | 浪费 8 种子 | 2 种子即定 |
| 解析层 | 无（用空回忆当代理） | **掩码剪枝**（确定） |

---

## 5. 诚实的边界说明

**这次测试没能证明"存在更好的算法"。** 它证明了：

1. ✅ **解析层不能替代战斗排序**（实验 1 负相关、实验 2 不显著）
2. ✅ **站位影响 > 回忆影响 3.7 倍**（实验 2，n=6，方向可信但幅度需更多样本）
3. ✅ **多数真实差距很大，1–2 种子粗筛已足够**（实验 3，n=7 对 × 10 种子，证据较强）
4. ✅ **固定阈值的失效点精确定位在临界对**（实验 3，可直接观测）

**仍需验证**：
- 实验 2 的"3.7 倍"基于 6 个配置。要作为设计依据，建议扩到 20+ 配置。
- "自适应加种子"能省多少预算，取决于临界对的比例。已知 2/7 ≈ 29% 的对差距 < 5%。**这个比例需要更大样本，且真实阵容下可能不同。**
- 掩码剪枝的实际剪枝率未测。可以零战斗算出来（枚举组合，看多少被剪）。
