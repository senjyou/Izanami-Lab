## 1. 核心发现：按均值排序会**越算越错**

我用你的真实 CV（11.68%）做蒙特卡洛。设定两个候选：

- **A**：你的 CV（11.68%），均值 = 你的实测均值
- **B**：均值低 3%，但 CV 高 1.7 倍（即"少配暴击率回忆、多留波动"的取舍）

**真实 Roll5**：A = 91,538,648，**B = 96,841,723** → **正确答案是 B**

两种排序器的命中率（各 400 次模拟）：

| 种子数 | 按**均值**选 | 按 **Roll5** 选 |
| ---: | ---: | ---: |
| 2 | 44% | 52% |
| 4 | 41% | 60% |
| 8 | 36% | 69% |
| 16 | 31% | 78% |
| 32 | **24%** | 88% |
| 64 | **15%** | 95% |
| 128 | **7%** | **100%** |

### 注意"按均值"那一列的走向

```
2 种子 → 44%
8 种子 → 36%
32 种子 → 24%
128 种子 → 7%
```

**种子越多，按均值选越错——最终趋近于 0%。**

**原因**：A 的真实均值确实高于 B（这是真的）。种子越多，均值估计越精确地收敛到 A——**但它精确地回答了一个错误的问题**。当两个候选的正确答案由 Roll5 决定、而均值排序指向相反方向时，**增加样本只会让你更确信那个错误答案。**

**这不是"精度不够"，是"目标函数错了"。** 补种子、加预算、优化调度——**全都没用，反而更糟。**

### 三种取舍下的稳定性

| B 的均值 | B 的 CV 倍数 | n=8 均值 | n=8 Roll5 | n=64 均值 | n=64 Roll5 |
| --- | --- | ---: | ---: | ---: | ---: |
| −1% | 1.7× | 41% | 70% | **34%** | 98% |
| −3% | 1.7× | 36% | 71% | **16%** | 98% |
| −1% | 2.5× | 44% | 85% | **42%** | 100% |
| −5% | 2.5× | 32% | 78% | **14%** | 100% |

**每一下降场景下，均值排序在 n=64 时都只有 14~42% 命中率——比随机猜还差。** 而 Roll5 排序在 n=64 时达到 98~100%。

## 2. Roll5 需要多少种子？（你的下一个质疑的答案）

用你的 CV=11.68% 测 Roll5 估计的稳定性：

| 种子数 | Roll5 估计偏差 | 估计的 sd | 相对误差 |
| ---: | ---: | ---: | ---: |
| 2 | **−5,612,283** | 7,658,525 | **8.36%** |
| 4 | −3,014,879 | 6,013,724 | 6.57% |
| 8 | −1,628,329 | 4,268,180 | 4.66% |
| 16 | −591,143 | 3,151,342 | 3.44% |
| 32 | −211,429 | 2,203,288 | 2.41% |
| 64 | −137,387 | 1,619,997 | 1.77% |
| 128 | ~−60,000 | ~1,100,000 | ~1.2% |

**两个关键点**：

1. **n=2 时 Roll5 偏低 561 万（6.2%）** —— 因为 2 个样本几乎描述不了上尾。
2. **偏差随 n 下降很慢**（n=64 仍有 −137,387 的负偏差）。**这是极值统计量的固有性质：上尾比均值难估得多。**

**所以对你的问题的最终回答**：

> **不是"1 个种子够不够"的问题。在 Roll5 目标下，1~2 个种子连 Roll5 都算不出来（偏差 6%+）。要稳定排序需要 16~32 个种子（78~88% 命中），要可靠需要 64 个（95%）。**

**这与作者算法完全相反**：他用 2/4/8 个种子估**均值**；Roll5 需要**几十个**。

## 3. 为什么"波动保护"是致命的设计错误

作者在 `quick_review.py:38` 的淘汰公式：

```python
cut = mean(D) > max(gap * reference, 3 * SE)
```

以及 `retain()` 的"波动/临界保护"——本意是**保守**，避免误杀。

**在 Roll5 目标下，这个机制变成了系统性筛掉正确答案的工具**：

| 作者机制 | 本意 | Roll5 下的实际效果 |
| --- | --- | --- |
| `3×SE` 惩罚 | 保护不确定的候选 | 高方差候选的 SE 大 → **更容易被留下？** 不——是被当成"噪声"而不被信任 |
| "波动保护"保留 | 保守 | **保留了低方差的平庸候选，高方差的潜力候选无法脱颖而出** |
| 按均值排序 | 找最好的 | **系统性选出 Roll5 更差的** |
| 多阶段缩小区间 | 提高精度 | **在错误统计量上越走越确定** |

**更严重的是**：作者花 256 个种子（最快复评末轮）去精确估计**均值**——而 Roll5 只需要 `均值 + 1.16296 × 标准差`，**两个量**。**同样的种子如果用来同时估计均值和标准差，就能直接算出 Roll5。**

## 4. 由此得到的明确修正

### 4.1 目标函数（一行改动）

```python
# 作者：
score = mean(samples)

# 修正：
C5 = 1.162964                # E[max of 5 standard normals]，两种独立方法验证
score = mean(samples) + C5 * stdev(samples)      # ≈ Roll5
```

**常数验证**（两种独立方法）：

| 方法 | 结果 |
| --- | --- |
| 数值积分（Simpson，60 万点） | **1.162964** |
| 蒙特卡洛（40 万次抽样） | 1.163234 |
| **用你的真实数据反查** | 预测 91,549,592 vs 实测 91,485,697，**误差 +0.070%** |

> 若担心分布非正态，可直接用模拟器已有的经验公式（`tactical_exercise.py:1062`）：
> `roll5 = Σ x_(i)·[(i/N)^5 − ((i−1)/N)^5]`。两者在你的数据上都可用。

**注意**：正态近似的前提已被你的数据验证（误差 0.07%），但**只验证了一个阵容**。若某些阵容分布明显偏斜，仍需用经验公式。

### 4.2 需要同时记录的统计量

不能只记录均值。每个候选需要**均值 + 标准差**（或直接存分位数）：

| 统计量 | 用途 |
| --- | --- |
| 均值 | 基线对比、诊断 |
| **标准差** | **计算 Roll5、识别高方差候选** |
| 分位数（p10/p50/p90） | 分布形状诊断，验证正态假设 |

### 4.3 采样策略

| 项 | 作者 | 修正 |
| --- | --- | --- |
| 单候选种子数 | 2 / 4 / 8（估均值） | **16~32 起步**（估 Roll5），关键候选 64 |
| 种子用途 | 缩小均值误差 | **同时估均值与标准差** |
| 粗筛 | 用均值淘汰 | **用 Roll5 淘汰**，且不得因方差大而淘汰 |
| 高方差候选 | 被"波动保护"边缘化 | **重点保护——可能是最优** |

### 4.4 一个直接可用的诊断

**用你现有的 100 场数据，任何阵容都能立刻算出 Roll5。** 所以：

- 用户手动测 100 场 → 已有 Roll5（你的模拟器已经显示）
- **优化器应该以"复现用户手动测试的 Roll5"为验收标准**
